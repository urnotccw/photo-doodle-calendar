# Photo Doodle Calendar Skill

把一张照片变成一张横向票券式月历：左边保留原照片，中间生成准确的月历，右边把照片主体转换成带留白的可爱手绘插画。

这个 Skill 来自多轮真实视觉迭代，重点解决的不是“让 AI 随便画一张日历”，而是稳定控制版式、日期、画风、留白和配色。

## 效果结构

```text
+----------------+-------------------------+--------------+
| 原始照片 30%   | 月份、年份、日历 45%   | 手绘主体 25% |
+----------------+-------------------------+--------------+
```

- 左侧：照片等比例铺满，保留主体和关键动作。
- 中间：月份位于左上角，年份位于右上角，日期严格对应真实星期。
- 右侧：粗糙蜡笔线条、轻微腮红、不完整填色，并保留明显留白。
- 全身人物：保留成年人的自然头身比、腰线和腿长；可爱感来自笔触与表情，不依赖大头短腿。
- 预览画布：约 16:9 横屏，外层象牙白区域只用于展示，不计入打印尺寸。
- 打印票券：只导出中间三栏票券，固定为 `25 x 10 cm`、`2953 x 1181 px`、`300 PPI`。同一系列每个月完全一致，不拉伸、不裁掉票券内容。

把整个 `photo-doodle-calendar` 文件夹放入 Codex Skills 目录：


重新打开 Codex 后，可以直接描述需求，也可以显式调用：

```text
$photo-doodle-calendar 用这张照片制作一张 2027 年 2 月的月历。
```

## 使用示例

```text
用这张照片做一个 2027 年 9 月的票券月历。右侧人物稍微可爱，但不要幼态，背景从照片中取色。
```

```text
沿用上一张的版式做下一个月。右侧人物缩小一些，四周多留白，不要圈日期。
```

## 工作流程

1. 读取照片，识别主体、动作、服装、配饰和主要颜色。
2. 根据目标年月计算日期网格，而不是让图片模型猜日期。
3. 从照片中选择一深一浅两种主色，分别用于日历和手绘面板。
4. 生成三栏票券：照片、日历、手绘主体。
5. 检查日期、年份、文字、留白、人物特征和手部结构。
6. 若局部有问题，只修改对应面板，避免整张图片越改越偏。

## 关键设计决策

### 为什么把日期网格写进提示词

图片模型擅长视觉风格，但不擅长独立推算日历。Skill 会先计算真实月份结构，再把每一行日期明确写入生成要求，降低错位、漏字和重复数字的概率。

### 为什么强调右侧留白

如果人物贴满右侧面板，画面会像普通人物海报，失去复古月历的轻盈感。Skill 将手绘主体控制在面板约 55%-65% 的面积，并要求四周至少保留约 15% 的完整背景。

### 为什么采用“局部重试”

生成式图片每次重画整张图，可能同时破坏已经正确的照片、日期或排版。因此 Skill 会判断问题属于照片、日历还是手绘面板，再只修改出错区域。

## 面试时可以怎么介绍

可以把它概括成一个“带视觉约束和校验闭环的图片生成 Agent Skill”：

- 输入层：读取用户照片与目标年月。
- 理解层：提取主体、动作、关键视觉特征和颜色。
- 确定性层：用真实年月计算日期网格。
- 生成层：将照片、结构化日历和风格化人物组合为票券。
- 评估层：检查日期、布局、留白、画风和主体一致性。
- 修正层：针对单个面板重试，减少无关区域漂移。

它体现了三个工程思路：把确定性计算和生成式模型分工；把用户的审美反馈转化为可量化约束；通过生成后的验证与局部重试提高稳定性。

## 已知限制

- 图片模型仍可能偶尔把小号日历文字画错，需要局部重试。
- 复杂手势、多人合照和大量遮挡会降低主体插画的稳定性。
- Skill 不会自动上传或公开用户照片；是否保存生成结果由用户决定。
